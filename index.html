Quick Start

Photon DB is an in-memory, Redis-style key-value database written in C++ from scratch, built as a semester project and modeled after the CodeCrafters "Build Your Own Redis" challenge.

You will learn

  • What Photon DB is and how it's structured
  • How to build and run it with Docker — no local C++ toolchain needed
  • How to talk to the server with redis-cli
  • Where the RESP parser, dispatcher, and command handlers live
  • How persistence works via RDB snapshots and an AOF log
  • How to contribute a new command or fix

What is Photon DB?

Photon DB speaks the RESP protocol (the same wire protocol Redis uses), so any Redis client — including redis-cli — can talk to it directly on port 6379. The whole team builds and runs it inside Docker, so everyone compiles against the same toolchain regardless of whether they're on Windows, macOS, or Linux.

Language
C++
Protocol
RESP (Redis wire protocol)

Build

Try it in 60 seconds

git clone https://github.com/AmritPant/photon-db
cd photon-db
docker compose build
docker compose run --rm dev

# inside the container
make
./photondb

From a second terminal, attach to the running container and connect with redis-cli:

docker ps
docker exec -it <container-name> /bin/bash
redis-cli -p 6379

127.0.0.1:6379> PING
PONG
127.0.0.1:6379> SET foo bar
OK
127.0.0.1:6379> GET foo
"bar"

Installation

You only need two tools installed on your machine — everything else runs inside a container.

Requirements

Git Docker Desktop

You do not need to install C++, g++, or make on your host machine — the Docker image already has them.

Step 1 — Get the code

git clone https://github.com/AmritPant/photon-db
cd photon-db

Step 2 — Build the Docker environment

docker compose build

This pulls down a Linux image with the compiler and tools (g++, make, redis-cli). It can take a few minutes on the first run and will be much faster afterward.

Step 3 — Open a dev shell and start the server

docker compose run --rm dev

This drops you inside the container with the project mounted at /workspace. From here:

make
./photondb

make compiles the project into the photondb binary. ./photondb starts the server on port 6379 and keeps running in the foreground — leave this terminal open.

⚠️ Port already in use? Something else on your machine is using 6379. Stop it, or remap the port by changing 6379:6379 to e.g. 6380:6379 in docker-compose.yml.

Architecture

A request travels through three main layers before it touches the in-memory store.

Request flow

TCP socket
   │
   ▼
RESP Parser        (include/resp-parser.h)
   │  raw bytes → std::vector<std::string> tokens
   ▼
Request Router / Dispatcher   (include/request-router.h)
   │  looks up the command name, dispatches to its handler
   ▼
Command Handler    (lib/request-handler/*.cpp)
   │  reads/writes the store, builds a RESP reply
   ▼
Store              (include/store.h, include/stream-store.h)
   │  in-memory hash map of keys, lists, and streams
   ▼
RESP-encoded reply written back to the socket

Core components

RESP Parser / Encoder
Converts raw socket bytes into command tokens, and encodes replies (bulk strings, arrays, integers) back into RESP.
Dispatcher
Routes a parsed command to the correct handler and manages transactions (MULTI/EXEC/DISCARD).
Store
store.h holds string and list keys with optional expiry; stream-store.h holds Redis-Streams-style entries.
Persistence
RdbParser.hpp and aof.hpp handle snapshotting and the append-only write log.

Directory layout

photon-db/
├── src/                 # entry point, config, AOF, RDB glue
├── lib/                 # implementation of core logic + handlers
│   └── request-handler/ # one .cpp per Redis command
├── include/             # headers for the above
│   └── request-handler/
├── frontend/             # Qt-based GUI client (Mainwindow.cpp/.h)
├── Dockerfile
├── docker-compose.yml
└── Makefile

There's also a small Qt frontend/ — a desktop GUI client, separate from the server itself — under active development.

Persistence — RDB & AOF

Photon DB supports two Redis-style persistence strategies so data can survive a restart.

RDB snapshots

RdbParser.hpp / Rdb.cpp read and write point-in-time binary snapshots of the store — the same idea as Redis's dump.rdb.

Append-only file (AOF)

aof.hpp / aof.cpp log every write command as it happens, so the database can rebuild its state by replaying the log. The appendonlydir/ folder in the repo holds the manifest for this log.

Configuration

Persistence behavior is wired up through config.hpp / config.cpp and aofconfig.cpp, which are read on startup in main.cpp.

Contributing

Photon DB uses a standard fork → clone → branch → pull request workflow.

Contribution flow

1. Fork the repo on GitHub
2. Clone your fork
   git clone git@github.com:<you>/photon-db.git

3. Create a branch
   git checkout -b feature/my-change

4. Make your change, build inside Docker, and test with redis-cli

5. Commit and push
   git push origin feature/my-change

6. Open a Pull Request against AmritPant/photon-db

Adding a new command

Each command is a self-contained handler pair:

  • Header in include/request-handler/<name>-command-handler.h
  • Implementation in lib/request-handler/<name>-command-handler.cpp
  • Registered in the dispatcher, include/request-router.h

List-type commands follow the same pattern one folder deeper, under request-handler/list-commands/.

Troubleshooting

Common problems the team has run into, and how to fix them.

"Cannot connect to Docker"

Open Docker Desktop and wait until it reports it's fully running, then try the command again.

"Port 6379 already in use"

Something else on your machine is bound to that port. Stop it, or change 6379:6379 to something like 6380:6379 in docker-compose.yml.

docker ps shows nothing

Make sure the container from the "run the server" step is still open in its own terminal, with ./photondb running.

Build is slow the first time

Normal — Docker is downloading the compiler and libraries. Subsequent builds are much faster since layers are cached.

⚠️ Push permission errors on the shared repo are usually an SSH key issue — make sure your key is added to your GitHub account and you're cloning with the git@github.com:... SSH URL, not HTTPS.
